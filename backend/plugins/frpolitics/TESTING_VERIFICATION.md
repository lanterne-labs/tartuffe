# Party Fact Verification Testing Guide

## Overview

This document describes the comprehensive testing framework implemented to verify that party facts generated by the frpolitics plugin accurately reflect the actual voting patterns of affiliated deputies.

## Testing Architecture

### Core Verification Components

1. **Party Fact Verification Logic** (`party_fact_verification_test.go`)
   - `VerifyPartyFactAccuracy()`: Compares party facts against actual deputy voting patterns
   - `VerifyDeputyPartyConsistency()`: Ensures deputy votes align with their affiliated party positions
   - `VerifyTemporalAffiliations()`: Validates deputy-party relationships are correctly established

2. **End-to-End Verification Tests** (`e2e_verification_test.go`)
   - `TestE2EPartyFactVerification()`: Full workflow test with controlled dataset
   - `TestRealDataPartyFactVerification()`: Integration test with real French National Assembly data
   - `TestPerformanceWithLargeDataset()`: Performance testing with larger datasets

## Test Execution Guide

### Running Individual Tests

```bash
# Run all verification tests

```

## Verification Methodology

### 1. Party Fact Accuracy Verification

The verification system validates that party facts correctly represent the majority voting behavior of affiliated deputies:

**Verification Process:**
1. Extract party facts from database
2. Collect all deputy votes for the same time period
3. Group deputy votes by party affiliation
4. Calculate actual majority position and ratio for each party
5. Compare against stored party facts

**Success Criteria:**
- Party facts should match actual deputy majority positions
- Consistency score ≥ 70% for test data
- Consistency score ≥ 80% for real data

### 2. Deputy-Party Consistency Verification

Ensures that individual deputy votes are consistent with their party's stated position:

**Verification Process:**
1. Cross-reference deputy votes with party positions
2. Identify discrepancies (deputies voting against party position)
3. Track temporal validity of affiliations

### 3. Temporal Affiliation Validation

Validates that deputy-party relationships are correctly established with proper time boundaries:

**Validation Process:**
1. Check affiliation existence in database
2. Verify temporal validity at vote time
3. Validate attribution completeness (organeRef, legislature)

## Quality Assurance

### Accuracy Thresholds

- **Minimum Acceptable**: 70% consistency for test scenarios
- **Production Ready**: 80% consistency for real data
- **Excellent**: 90%+ consistency

### Discrepancy Categories

1. **Threshold Errors**: Party facts generated when majority below threshold
2. **Calculation Errors**: Incorrect majority position determination
3. **Affiliation Errors**: Missing or incorrect deputy-party relationships
4. **Temporal Errors**: Affiliations outside valid time ranges
